# Contributing to the Elastic Email Angular SDK

Thanks for taking the time to contribute! This document explains how to report problems, suggest changes and submit pull requests.

## Before you start: this SDK is generated

Almost everything in this repository (`api/`, `model/`, `api.module.ts`, `configuration.ts`, `encoder.ts`, `index.ts`, `param.ts`, `variables.ts`) is generated by [OpenAPI Generator](https://openapi-generator.tech) from the Elastic Email API specification.

This means:

- **Manual edits to generated files will be overwritten** by the next release.
- If an endpoint, model, parameter or description is wrong or missing, the fix belongs in the API specification. Please [open an issue](https://github.com/ElasticEmail/elasticemail-ts-angular/issues/new/choose) describing the problem. We'll fix it upstream and regenerate the SDK.
- Pull requests are most useful for non-generated content: documentation, examples, tests, build and CI configuration, and repository tooling.

If you're not sure whether something is generated, open an issue first and ask.

## Reporting bugs

Search [existing issues](https://github.com/ElasticEmail/elasticemail-ts-angular/issues) first. If nothing matches, open a new issue using the **Bug report** template and include:

- SDK version (from npm, e.g. `4.2.0`; run `npm ls @elasticemail/elasticemail-client-ts-angular`)
- Angular version (`ng version`), RxJS and TypeScript versions, and whether the call runs in the browser or with Angular SSR
- The API method you called and a minimal code sample
- The full error message and HTTP status code (`error.status` and `error.error` from the `HttpErrorResponse`)

**Never paste your API key** into an issue, log or code sample.

Questions about your Elastic Email account, sending limits, deliverability or billing aren't handled in this repository. The preferred way to get help is the **chat widget on [elasticemail.com](https://elasticemail.com)**.

Looking for sample code? See the [Elastic Email examples repository](https://github.com/ElasticEmail/elasticemail-examples), including the [Node.js examples](https://github.com/ElasticEmail/elasticemail-examples/tree/main/nodejs-elasticemail-examples).

## Suggesting features

Open an issue using the **Feature request** template. Describe the use case first and the solution second. It helps us decide whether the change belongs in the API, the SDK or the documentation.

## Security issues

Please do **not** report security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

## Development setup

Requirements: [Node.js](https://nodejs.org) and npm (a version supported by Angular 19).

```bash
git clone https://github.com/ElasticEmail/elasticemail-ts-angular.git
cd elasticemail-ts-angular
npm install
npm run build
```

`npm run build` packages the library into `dist/` with [ng-packagr](https://github.com/ng-packagr/ng-packagr). Keep the library compatible with the Angular, RxJS and TypeScript ranges in `package.json`, and don't add new dependencies without discussing it in an issue first.

## Pull requests

1. Fork the repository and create a branch from `master` (`git checkout -b fix/short-description`).
2. Keep each change focused. One logical change per pull request.
3. Make sure `npm run build` passes.
4. Update documentation if your change affects how the SDK is used.
5. Open a pull request against `master` and fill in the template.

A maintainer will review your pull request and may ask for changes. When a change touches generated code, we may apply it upstream instead of merging the PR directly. You'll still get credit in the release notes.
